The work implements an explicit TypeORM `DataSource` with `synchronize: false` and `migrationsRun: false`, independent `migrate:deploy` and `migrate:status` commands, an ordered migration/step ledger with `schema_version`, deterministic fingerprints over SQL, structured configuration and callback source, and synthetic MariaDB integration fixtures. Migrations require distinct `MIGRATION_DATABASE_*` credentials, a database-scoped migration role, preflight checks, UTC/strict SQL mode, a bounded statement timeout and a per-database advisory lock.

## Issue criteria

| Criterion | Result and evidence |
|---|---|
| Empty database reaches current schema; repeat does not repeat DDL | Passed. Harness starts empty, applies schema versions 1 and 2, reruns `deploy` concurrently and serially, then reports both migrations `APPLIED` with matching checksums. |
| Concurrent executors do not duplicate migration work | Passed. Two `deployMigrations` calls run concurrently on the partial initial schema and again after migration; a held MariaDB `GET_LOCK` proves timeout behavior. |
| Recovery after MariaDB implicit-commit DDL | Passed. A child exits after tenant-table DDL before the journal step is marked; restart verifies the table shape and resumes. A second injected process exit after a committed backfill batch resumes using its saved cursor. The README documents that MariaDB DDL commits implicitly and recovery is verify-and-forward, not rollback. |
| Previous release remains compatible through expand/backfill | Passed locally. N-1 writes only `display_name` while backfill is paused, including an ID lower than the diagnostic cursor; the expand triggers fill `external_name`. An N-1 insert and update after backfill are also synchronized. Validation rejects mismatches. |
| Tenant/asset/session index plans use scoped indexes | Passed locally with synthetic volume. After loading 10,000 assets and 10,000 test-only session rows and running `ANALYZE TABLE`, unforced EXPLAIN plans choose `ix_ca_meta_asset_tenant_kind_created` and `ix_m203_session_tenant_live`; neither plan reports a full scan. The asset table also has candidate key `(tenant_id, id)` for future child FKs. |
| String IDs and UTC timestamps preserve exact values | Passed locally. The fixture checks a numeric-looking app ID, Unicode/emoji external ID, an external ID with a significant trailing space, a 512-character multibyte external ID (1,024 UTF-8 bytes), strict rejection at 513 characters, and exact `DATETIME(6)` round-trip. `utf8mb4_nopad_bin` preserves trailing-space distinctions. |
| Backup and restore are tested | Passed for synthetic data. A `--single-transaction` MariaDB dump is restored into a fresh database; the harness verifies 10,005 asset rows, both applied schema versions, the exact UTF-8 ID bytes and microsecond timestamp. |

The `switch`/`contract` phases are supported by the step model but are not run destructively in this package. M2 has no consumer migration to switch to `external_name`; the old `display_name` column and N-1 synchronization triggers remain until consumers confirm the new field and the rollback window closes. This follows issue #22's instruction to delay removals. The persistent session schema belongs to M3; the session EXPLAIN table is a test-only fixture derived from accepted M1.05 shape.
