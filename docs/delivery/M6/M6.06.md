Run from the repository root with Node 24.22.2 or a compatible Node 24 runtime; no npm installation, Docker, DB, credential, network request or external service is required:

```powershell

```

The check reads the tracked ledger and writes no files. It validates the state of this preparation record only; it cannot verify GitHub, artifact signatures, image digests, infrastructure, ownership or operation.

## Promotion checklist

Before an authorized release operator can ask for a production go/no-go, record evidence outside this source checkout and bind it to one immutable milestone commit:

1. Confirm target ownership, least-privilege service accounts, network/ingress, DNS/TLS, database/queue, volumes, capacity and secret-store references. Keep raw secret values outside the manifest; use opaque references only.
2. Integrate and revalidate M6.01–M6.05 on the candidate. Confirm required CI checks on that exact SHA and verify the M2.09 release manifest, web/API digests, worker/API digest identity, SBOM, provenance and Trivy reports from their original artifacts.
3. Run M2.10 structural preflight with protected staging inputs, then perform separate authorized staging smoke for DNS, TLS, health/readiness, callbacks, signed webhooks and per-flow Meta configuration. Keep each journey and Instagram variant separate. Synthetic fixtures do not satisfy these checks.
4. Verify schema N/N-1 compatibility, migration dry-run and health preflight. Confirm a recent consistent backup and a restore result before any expand/backfill. Preserve the prior manifest and explicit abort/rollback owner.
5. Confirm protected GitHub staging/production environments, reviewers and deployment gates by reading the actual current ruleset/configuration. A checked-in workflow does not prove branch/environment protection.
6. Have product, security and operations review the per-flow eligibility, tenant isolation, capacity, restore, rollback, support plan and residual risks. Record named approvers/operators and timestamped decisions without customer data or credentials.
7. Keep new-tenant/channel activation and legacy routing unchanged until the responsible operator authorizes the specific production plan. A rollback of code does not reverse sent messages, Meta grants/subscriptions, or other external effects; reconcile those separately and never replay ambiguous sends or restore revoked authorization.
