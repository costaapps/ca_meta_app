# M6.02 local security assessment

Issue: [#70 — Auditar isolamento, OAuth, cofre e superfícies privilegiadas](https://github.com/costaapps/ca_meta_app/issues/70).

## Scope and method

This assessment reviews the M6.02 threat areas against the current API implementation, the accepted identity/security contract, and the existing focused security tests. It adds a reproducible local runner and a narrow static check for GitHub Actions and runtime container boundaries. Tests use synthetic tenants, identities, credentials, webhook bodies, and redaction markers only.

The runner selects 28 existing API test files. It compiles the API/test TypeScript once, runs only the selected tenant, identity, OAuth, session, credential, privacy, webhook, support, notification, migration, and HTTP-boundary tests, then checks workflow references/triggers and Docker runtime users/ports. See [`tools/m6-02/README.md`](../../tools/m6-02/README.md) and [`run-security-validation.mjs`](../../tools/m6-02/run-security-validation.mjs) for the complete selection and setup.

This is a local code/configuration review, not a penetration test. The checked-in tests do not prove every endpoint or every deployment configuration. No test contacted Meta, Suite4, staging, production, or a third-party asset. No real customer data or secret was used.

## Finding and correction

The base lock resolved Angular runtime packages at `21.0.8`. `npm audit --omit=dev` reported six HIGH package findings affecting `@angular/common`, `@angular/compiler`, `@angular/core`, `@angular/forms`, `@angular/platform-browser`, and `@angular/router`. The advisories covered cross-request transfer-cache leakage/state poisoning ([GHSA-39pv-4j6c-2g6v](https://github.com/advisories/GHSA-39pv-4j6c-2g6v), [GHSA-jhpw-976m-542j](https://github.com/advisories/GHSA-jhpw-976m-542j)), formatting denial of service ([GHSA-48r7-hpm6-gfxm](https://github.com/advisories/GHSA-48r7-hpm6-gfxm), [GHSA-p3vc-36g9-x9gr](https://github.com/advisories/GHSA-p3vc-36g9-x9gr)), compiler/core sanitization and XSS issues ([GHSA-g93w-mfhg-p222](https://github.com/advisories/GHSA-g93w-mfhg-p222), [GHSA-jj27-h5hq-8x99](https://github.com/advisories/GHSA-jj27-h5hq-8x99)), and Angular Router SSR denial of service ([GHSA-ff3f-86qr-9cv3](https://github.com/advisories/GHSA-ff3f-86qr-9cv3), [GHSA-62vg-58rm-qff7](https://github.com/advisories/GHSA-62vg-58rm-qff7)). The audit also reported related Angular advisory records for the affected packages; the exact installed versions and final audit output below are the package-level retest evidence.

Only the Angular 21 dependency line changed: runtime Angular packages and `@angular/compiler-cli` are pinned to `21.2.26`; `@angular/build` is `21.2.30` and `@angular/cli` remains at the base-resolved `21.0.5`. A provisional build/CLI pair at `21.0.5` failed to compile Angular `21.2.26`'s `ChangeDetectionStrategy.Eager`; keeping the newer build compiler fixed that compatibility issue while the older CLI wrapper still builds successfully. No broad `npm audit fix` was run.

The final lockfile normalizes the Web workspace's duplicate dependency paths. The unchanged M2.08 comparator was run locally against the exact `f09c12df0cbd77be4f4271d71e08c13e1913a781` base and reported **0 new advisory/package/path/scope entries and 0 severity escalations**. Current root-workspace audit counts are 37 development-only findings; runtime counts are zero. The scanner/workflow policy was not changed. The focused M2.08 image job still fails on the API image; the allowed GitHub connectors exposed only the exit code, severity filter and report artifact reference, not the report contents, so the exact image finding is **Not confirmed**.

The final `npm audit --omit=dev` reports **0 total vulnerabilities**. `npm ls` confirms the installed Web workspace resolves the pinned patch versions. The scope does not claim that development-only or image vulnerabilities are absent; their diff-based CI evidence remains pending.

No blocking API source defect was exposed by the selected local suites, so this package does not alter `apps/api/src` or its tests.

## Residual risk and release condition

**Not confirmed:** the API image scan finding and its remediation; authorized staging tests for every endpoint; two-process multi-tenant/grant-conflict scenarios; live Suite4/iframe/source identity; real CORS/redirect/edge rules; production vault key rotation/backup/revocation; and the active GitHub ruleset. The local static check and dependency comparison do not replace CI image scanning or a scoped penetration test.

Owner: M6 release/security reviewer. Deadline: before promotion of any release depending on these flows. Compensating control: keep the dependent scenario out of production until the staging/security evidence is attached to the release candidate. This is a release hold, not a security waiver.
