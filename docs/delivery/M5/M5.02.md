# M5.02 — Connections, assets and verifiable status

## Scope

Issue [#56](https://github.com/costaapps/ca_meta_app/issues/56), implemented on `desktop/m5-02` over the M5.01 candidate `d2ccb6227c50b00c5bdfc55642f42381eb5831b1`. The focused follow-up below addresses a review finding on candidate `cdb8c7869914e5f66f9ec46f5a56998d86e72c80`.

The portal reads tenant-scoped `/connections` and `/connections/:id`. The API exposes only sanitized `displayLabel` values sourced from server-owned asset names, masks WhatsApp phone-like strings, and does not fall back to provider identifiers. Connection filtering by channel, exact configured journey, status (including stale evidence), and exact WhatsApp number is applied in SQL before cursor pagination. The UI resets filters and cursor state and clears loaded data after the authenticated context changes.

The detail view separates connection readiness, asset status, authorization, credential health, webhook/subscription, and enterprise projection. It preserves UNKNOWN, PARTIAL, stale and revoked meanings; request IDs are inside expandable support details. Four WhatsApp phone assets are represented as distinct rows, use opaque internal asset IDs in the refresh client method, and show safe masked labels or an explicit unconfirmed-label fallback.

## M1.08 identity gate

The current `SessionContext` contract contains `tenantRef` but no safe `tenantDisplayName`. Both list and detail show **“Identidade da empresa não confirmada”** and keep all tenant-scoped write controls unavailable. Server-scoped reads continue. Capability flags control whether reauthorization/disconnect explanations are shown; viewers receive no controls because the API capability snapshot sets them false, and the existing server authorization still denies viewer writes. No refresh job is requested or shown as successful while the action is unavailable.

This leaves manual refresh initiation and in-screen job polling pending the accepted M1.08 tenant-label/host-context gate. The existing refresh adapter is not registered; a request would fail closed rather than make a Meta call. M4.12 supplies local coalescing evidence only. No provider, sandbox or production behavior is claimed.
