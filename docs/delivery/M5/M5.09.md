## Independent review correction

The review of earlier candidates found that cutover could omit matched shadow evidence and cohort rollback did not accept an interrupted partial writer matrix. The correction requires a read-only `MATCHED` shadow report for the same cohort whose legacy snapshot hash equals the reconciled current source hash. The SQL store also requires every function to have entered shadow-read and keeps the same drift/candidate snapshot evidence across partial cutover. Rollback handles current `PREPARED`, `SHADOW_READ` and `CUTOVER` rows atomically; cut-over functions return to their recorded owner, untouched functions remain on legacy, and a cut-over credential reference whose previous owner was legacy stays central.

The latest residual review correction re-reads the candidate via the repository's configured read-only port during each writer switch and requires its current source version and snapshot hash to equal the report. The focused unit test covers a matched report followed by a candidate update. The read and SQL CAS are not one distributed transaction; a source change after the re-read but before the CAS remains possible until a real adapter supports a pinned version or conditional read.

The root `node_modules` in the implementation environment was a shared junction whose `@ca-meta/contracts` declarations came from another checkout. To typecheck this worktree without touching that target, validation temporarily added an ignored `apps/api/node_modules/@ca-meta/contracts` junction to this worktree's package. No package lock or tracked dependency changed; a clean `npm ci` workspace resolves the local package normally. All database evidence remains synthetic and isolated.

If a local disposable MariaDB service and authorized local test password are available, also run `npm run test:m5-09:db --workspace=@ca-meta/api`; the runner only accepts loopback and random temporary schema/users.
