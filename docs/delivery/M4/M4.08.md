## Implementation details

- Added bounded Facebook Page discovery orchestration. The typed M4.04 Graph client rejects incomplete pages/cursor loops before vault enrollment; M4.08 rejects partial results, duplicate Page IDs/credential refs and malformed metadata before persisting Page assets. Discovery is bounded to 500 Pages.
- Keeps `tasks` as observations, never permission grants. The current Page capability snapshot reports Page status, comments and messaging as disabled with `PERMISSION_MAPPING_NOT_CONFIRMED`.
- Adds Page selection/reconciliation to the existing generic M4.11 targets and bindings. Desired selection is persisted under tenant/app/environment/Page asset/authorization; schema v18 is sufficient, so no migration was added.
- Adds portal-session selection/status endpoints. `RESOURCE_READ` cannot change desired selection; replacement requires `CONNECT` and global CSRF checks.
- Adds a focused harness and synthetic test source for pagination, token-to-Page mapping, zero Pages, fail-closed partial pages, duplicate cursor handling, task/grant separation and M4.11 regression behavior.
- Official source evidence for discovery is limited to Meta's [Facebook API collection](https://www.postman.com/meta/facebook/documentation/r56bjfd/facebook-api): `GET /me/accounts?fields=name,access_token,tasks`, cursor pagination, and Page Access Tokens acting for Pages the user may manage. It does not confirm app-specific scopes/grants or `subscribed_apps` behavior for Pages.

## Gaps and limits

- `MetaGraphFacebookPagesProvider` consumes M4.04's typed `/me/accounts` method, but is not registered. It requires a server-owned resolver context; the existing credential resolver only accepts verified asset authorizations and cannot provide the initial user-token handle from an authorization UUID. The vault also lacks tenant-scoped credential enrollment metadata support. M4.08 adds no ad-hoc SQL or token storage.
- The M4.03 saga does not yet provide the trusted service actor needed to call M4.11 from the worker; `FacebookPagesOnboardingAdapter` requires an actor resolver.
- The Page selection/status HTTP route is implemented and contract-generated, but not runtime-tested. No M4.03 Facebook adapter is registered because OAuth provider configuration, initial user-token resolution and vault enrollment are absent.
- Projection remains behind a fail-closed port. Page subscription endpoint, fields, permission grants, app review, token expiry/data access expiry, current Graph version and live callback route are **Not confirmed**.
- The `MetaGraphSubscriptionProvider` performs no Page request; only the desired binding is written. A local fixture cannot certify real Page subscription behavior.
- No real Meta call, credential, account, Page, production subscription, WhatsApp template or phone was used.
