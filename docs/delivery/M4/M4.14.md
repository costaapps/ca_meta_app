## Candidate evidence

This package adds a deterministic synthetic evidence crosswalk and focused tests for M4.14 release invariants and local adverse cases. The evidence fixture contains the required four-flow × seven-scenario matrix and links each local assertion to its exact executable test name. The focused spec verifies that those test names remain present in their source files, that all 28 minimum cells are represented, and that unconfirmed external gates remain explicit.

The crosswalk currently has **0 fully certified minimum cells** and **28 partial-local cells**. Each of the four flows has a bounded local test reference for success boundaries, cancellation, partial permission, replay, timeout/expiry, reauthorization, and disconnect. These checks do not establish full end-to-end provider behavior; each row retains its remaining gap. This pack does not satisfy an external Sandbox gate.

The new App Review gate test constructs five synthetic exact Meta auth profiles, leaves App Review and Sandbox eligibility unconfirmed, and proves that all capability rows stay disabled, profile resolution returns no configuration, and the onboarding resolver remains unavailable. The Coexistence message capability reaches the explicit `APP_REVIEW_NOT_CONFIRMED` reason.

The credential selection test constructs two synthetic Instagram Login credential candidates, proves that the exact server policy selects its preferred candidate, verifies a different Instagram auth variant cannot consume the opaque one-use handle, and confirms the selection audit/vault callback identify the selected synthetic credential while the returned handle/result and audit do not expose the secret marker.

The 12 originally uncovered local adversity cells were addressed through existing contract seams and are now partial local evidence: Facebook partial permission and reauthorization; Instagram cancellation, partial permission, reauthorization and disconnect; exclusive WhatsApp cancellation, partial permission, reauthorization and disconnect; and Coexistence cancellation and disconnect. The targeted tests use exact auth profiles, keep prior grants active when permissions/config are blocked, consume only matching cancellation state, prevent code replay after cancellation or expiry, and keep disconnect scoped to one resource while provider cleanup remains blocked. The fixture links each row to the exact case and its residual limitation.
