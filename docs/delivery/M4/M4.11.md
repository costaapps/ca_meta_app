## Integration changes

- `apps/api/src/app.module.ts` registers `MetaSubscriptionsModule` with the existing dynamic `MetaAssetsModule`, `MetaGraphModule`, and `MetaAppConfigModule` instances. The integration does not construct another database, Graph client, app-config registry, or credential resolver.
- `apps/api/src/database/migrations/migrations.ts` registers `META_SUBSCRIPTIONS_MIGRATION` and all `META_SUBSCRIPTION_TABLES` in the migration and domain table registries.
- `apps/api/test/fixtures/m4-11-subscriptions.ts` seeds generated synthetic tenant/app/authorization/credential-metadata/WABA/four-phone rows and verified phone-to-account relations.
- `apps/api/test/m4-11-meta-subscriptions.integration.spec.ts` deploys the registered migration set in the gated disposable MariaDB profile, resolves four phones through the catalog, proves that one phone with two eligible grants fails closed without a selector and resolves each grant only when selected, concurrently creates four base bindings, adds the second grant, repeats all five bindings concurrently, and removes only the selected grant. `MysqlMetaSubscriptionStore.ensureBinding` retries only MariaDB deadlocks and lock-wait timeouts, at most four total attempts with 20/40/60 ms delays; every attempt uses a fresh QueryRunner, and rollback and release complete before backoff. The assertions require a single target, five unique active bindings after repeated upserts, then four remaining active bindings (three other phones plus the other grant for the selected phone) with target desired state still `SUBSCRIBED` after disconnect.
- `apps/api/tsconfig.m4-11-test.json` and `tools/m4-11/run-focused-test.mjs` include the MariaDB fixture in the one M4.11 focused harness. The harness compiles into OS temporary output and cleans that directory on completion.

## Evidence and limits

The focused command was **not run by this implementation agent**, per coordinator instruction. No tests, builds, CI, dependency installs, commits, or pushes were performed here. The coordinator should run the focused command at the integrated candidate SHA and record that SHA, environment/profile, Node/npm versions, and result.

The MariaDB test uses generated UUIDs, synthetic provider IDs, and a `SYNTHETIC_FIXTURE_ONLY` credential metadata row without secret material. It uses only `MysqlMetaSubscriptionCatalog` and `MysqlMetaSubscriptionStore`; it does not instantiate a Graph adapter or issue network requests. The fixture leaves UUID-scoped rows and append-only audit rows in the disposable MariaDB profile. The harness removes only its OS temporary compilation directory; discard the disposable profile through its owning environment workflow.

Meta's exact permission grants, Graph version availability, GET interpretation, response shape, request-body behavior, Page/Instagram support, app-level Webhooks mutation, and remote unsubscribe semantics remain **Not confirmed**. This fixture proves local migration registration and MariaDB store behavior; it is not provider certification or proof of deployed PHP behavior.
