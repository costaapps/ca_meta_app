# M3.03 / issue #31 — implementation evidence

## Scope and acceptance evidence

This package implements direct sign-in for a previously invited identity with an active membership. It does not create principals, tenants, or memberships. Only the in-memory fake inbox is enabled in `development` and `test`; staging and production use a disabled transport until a provider is separately approved and configured.

| Criterion | Local evidence | Limitation |
|---|---|---|
| GET/HEAD scanners do not consume links or create sessions | `apps/api/test/m3-03-magic-link.spec.ts`; GET renders a no-store/no-referrer explicit confirmation action and HEAD is read-only. | Browser/provider scanner matrix remains Not confirmed. |
| One-use token cannot replay, choose another tenant, or survive membership revocation/expiry | Focused tests cover concurrent consume, replay, expiry, stale/revoked membership and two active tenant choices. Store rechecks current membership/version while holding the link and membership locks in one transaction. | The SQL row-lock behavior has not been exercised against MariaDB; migration registration is pending integration after M3.06 v7. |
| Public errors do not expose invited-member listings | Known and unknown requests return the same accepted response; consume failures share a safe public error and no endpoint lists invitations. | Constant-time or timing non-enumerability is Not confirmed; local tests establish response equality only. |
| Rate limits and quotas prevent unrestricted delivery | Local abuse buckets cover source IP, normalized identity and tenant; queue deduplication is tested. Delivery performs at most one automatic attempt. | Limits are process-local and do not establish distributed or production quota behavior. |
| Link tokens are not stored/logged in clear | DB stores a SHA-256 token hash; the opaque token is derived from an internal random identifier with an HMAC key. Response/event paths omit token; token delivery remains in the local fake inbox only. | Production log review and provider delivery evidence await the integrated environment/provider gate. |
